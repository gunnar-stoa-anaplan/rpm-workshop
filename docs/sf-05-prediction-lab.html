Sales Forecasting AI Prediction Lab

The Anaplan Prediction surfaces, the Forecaster algorithm panel, and how Sales Ops chooses the model that runs the org

Sales Forecasting Module 45 min

Anaplan Prediction is the AI layer of Sales Forecasting. The platform ships with the Forecaster sub-engine, which trains a panel of statistical and machine-learning algorithms on the organization's own historical sales data, generates a baseline forecast at a chosen confidence level, and exposes the result back into the planning loop. Reps and managers see the baseline next to their commit. Sales Ops controls which algorithm and confidence level the organization runs on. This page walks through the two in-app surfaces, the actual algorithm catalog, and the lab exercises for calibrating both.

What you'll do

  • Recognize the two Anaplan Prediction surfaces and which persona uses each
  • Read the Prediction Variance table and identify the winning algorithm × confidence level pair from the SPM Foundational panel (ETS, SARIMAX, Prophet, TimesFM, LightGBM, MULR/MVLR, DeepAR)
  • Run the BT backtest actions to validate accuracy before activating a live algorithm
  • Apply an override via Override Algorithm + Override Confidence Level (P1 / P2 / P3) and confirm it propagates to the rep / manager dashboard
  • Verify each lab end-to-end with the inline Check my Work button

Two Surfaces, Two Personas

The app has two distinct AI Prediction pages — one for reps and managers, one for Sales Ops / RevOps. They show overlapping data but support different actions.

Anaplan Prediction (rep / manager view)

The forecast-accuracy comparison view. Compares the team's submitted forecast against the Anaplan model's predictions and tracks variance over time. Read-only for reps and managers; this is where they understand the quality of their own forecast against the model's.

Anaplan Prediction — Sales Ops

The algorithm control surface. Evaluates multiple forecasting algorithms, compares their historical accuracy, drills into the specific factors driving each prediction, and selects the model applied across the organization. Sales Ops / RevOps only.

The Forecaster Architecture

The Forecaster reads from a Historical Data by Hierarchy module (the trailing actuals plus open opportunity inputs), runs each candidate algorithm against that data, and writes back into a set of Forecast Results modules. Sales Ops reviews the suggested algorithm and confidence level for each entity; if they accept the suggestion, results flow into the rep / manager Anaplan Prediction dashboard. If Sales Ops overrides the algorithm or confidence level for a given entity, the override path routes through the Sales Ops dashboard first.

Anaplan Prediction Methodology — how to override

From the in-app docs, the override workflow is exactly two steps:

  1. In Override Algorithm, select an algorithm.
  2. In Override Confidence Level, select a confidence level (P1, P2, P3).

Confidence levels P1 / P2 / P3 correspond to the percentile bands the Forecaster outputs — P1 is the tightest (most-likely) band, P3 the widest. Sales Ops pick the level appropriate to how aggressive vs. conservative the org wants its baseline to be.

Actuals vs Anaplan Forecast Comparison

💡 BT = Backtest

Each algorithm also ships in a BT variant in the Forecaster Actions list (e.g. Prophet T1 BT) — the same algorithm run on a rolling historical window so accuracy can be measured before it's used in production. Standard practice: run the BT variants first, read the Prediction Variance table, enable the live action only for what wins.

Algorithm Explained

A drill-down narrative for the currently selected algorithm — what it does, what assumptions it makes, and when it tends to win or lose against the rest of the panel. Useful for Sales Ops who need to explain a model choice to Finance or Sales Leadership without hand-waving.

Forecaster Algorithm Details

A table showing each algorithm's forecast values across multiple time periods, alongside historical completed periods and future projected periods. This is the surface where you check that an algorithm's forecast curve is shaped right before activating it.

Prediction Factors Considered

To the right of the algorithm-details table, a panel listing the specific signals and patterns the selected algorithm is using to generate its forecasts — seasonality, trend changepoints, regressor coefficients, feature importances, etc. This is the explainability surface for the active model.

The Operating Loop

1. Backtest

Sales Ops runs the BT Forecaster Actions across the algorithm panel and reads the Prediction Variance table to identify which algorithm wins at which confidence level (P1 / P2 / P3) for each entity.

2. Override & Activate

For each entity where the winning algorithm differs from the panel default, Sales Ops uses Override Algorithm + Override Confidence Level to set the right model. The live (non-BT) Forecaster Action then runs forward.

3. Review & Publish

The baseline flows into the rep / manager Anaplan Prediction dashboard. Reps and managers see it alongside their commit. Sales Ops monitors Avg. Prediction Variance vs. Avg. Day-1 Forecast Variance to validate the choice is working.

Lab A — Backtest the algorithm panel

Run the backtest variants of each Forecaster algorithm against the demo dataset and identify which algorithm wins per entity and per confidence level.

  1. Open the SF demo workspace and navigate to Sales Forecast → Anaplan Prediction — Sales Ops.
  2. From the underlying Anaplan Prediction Forecaster, identify the SPM Foundational BT variants (ETS T1 BT, SARIMAX T1 BT, Prophet T1 BT, TimesFM T1 BT, LightGBM T1 BT, MVLR T1 BT).
  3. Run each BT action against the trailing-24-month actuals window.
  4. Back on the Sales Ops dashboard, read the Prediction Variance table. For each algorithm row, note the variance at P1, P2, and P3.
  5. Identify the winning algorithm × confidence level pair — the cell with the smallest variance.
  6. Compare your choice to the Anaplan Prediction Methodology Applied KPI. Is the org already running on it, or is there a meaningful change to recommend?

Lab B — Override and publish a new baseline

Apply the algorithm + confidence-level winner from Lab A as the active methodology, publish the baseline, and validate it lands on the rep / manager dashboard.

  1. On the Anaplan Prediction — Sales Ops page, go to Anaplan Prediction Methodology.
  2. In Override Algorithm, select the winner from Lab A.
  3. In Override Confidence Level, select the winning P-level.
  4. Confirm the Anaplan Prediction Methodology Applied KPI updates to show your selection.
  5. Open Algorithm Explained and read the narrative — make sure you can repeat the reasoning out loud in plain English.
  6. Open Prediction Factors Considered and identify the top 3 signals the algorithm is using.
  7. Switch to the Anaplan Prediction (rep / manager) page and confirm: the Anaplan Prediction KPI updated, the trend chart now reflects the new baseline, and Prediction Variance Comparison shows the expected delta vs. the manual forecast.
💡 What "confidence" actually means

P1 / P2 / P3 are percentile bands of the algorithm's predicted distribution. P1 is the tightest band (narrowest forecast range); P3 is the widest (most cautious forecast range). The confidence-level choice is a business decision as much as an accuracy decision — pick P1 when leadership wants a sharp baseline they'll defend; pick P3 when leadership wants headroom and the freedom to land above the model.

Operating Cadence

  • Weekly — re-run the live Forecaster Actions and confirm Avg. Prediction Variance is still in a healthy range on the Sales Ops dashboard.
  • Monthly — re-run the BT variants, re-read the Prediction Variance table, rotate the active algorithm if a different one is now winning.
  • Quarterly — full retrain with refreshed actuals, audit Prediction Variance Comparison vs. landed numbers, and validate any standing overrides are still justified.
⚠ Human-in-the-loop, always

The Anaplan Prediction output is a baseline, not the final forecast. Reps and managers still own the commit. Positioning this in customer conversations matters: if Sales Ops uses Forecaster output as an automatic override of rep commits, trust in the app collapses immediately. Sell it as a coaching and triage tool, not a replacement for the call.

✅ Do — Calibrate

These are the three questions customers always ask.
